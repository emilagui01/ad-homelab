>_Invoke-LabBuild—☐✕

Build steps

PS C:\Labs\emillab> Invoke-LabBuild -Verbose

[1/6]Enable Hyper-V and create the lab network

Created an internal virtual switch and a NAT rule on the host so the lab stays isolated from my home network but can still reach the internet (needed to activate the evaluation OS).

# On the host laptop (JARVIS), elevated PowerShell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
New-VMSwitch -Name "LabSwitch" -SwitchType Internal
New-NetIPAddress -IPAddress 192.168.50.1 -PrefixLength 24 -InterfaceAlias "vEthernet (LabSwitch)"
New-NetNat -Name LabNAT -InternalIPInterfaceAddressPrefix 192.168.50.0/24

[2/6]Install Windows Server 2022 and configure DC01

Generation 2 VM, 2 vCPUs, 4 GB RAM, 60 GB disk. Renamed the server, assigned a static IP, and pointed DNS at itself in preparation for the DNS role.

Rename-Computer -NewName DC01 -Restart
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.50.10 -PrefixLength 24 -DefaultGateway 192.168.50.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 127.0.0.1
Set-TimeZone -Id "Central Standard Time"

[3/6]Promote DC01 to a domain controller

Installed Active Directory Domain Services and created a new forest, emillab.local, with integrated DNS. Took a Hyper-V checkpoint immediately after so the domain could be rolled back if later changes broke it.

Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "emillab.local" -InstallDns
Get-ADDomain   # verify the new domain

[4/6]Configure DNS forwarding and DHCP

Added a forwarder so domain clients can resolve internet names, then installed DHCP, authorized it in Active Directory, and created a scope that hands out the gateway and DC as DNS server.

Add-DnsServerForwarder -IPAddress 8.8.8.8
Install-WindowsFeature DHCP -IncludeManagementTools
netsh dhcp add securitygroups
Restart-Service dhcpserver
Add-DhcpServerInDC -DnsName dc01.emillab.local -IPAddress 192.168.50.10
Add-DhcpServerv4Scope -Name "Lab" -StartRange 192.168.50.100 -EndRange 192.168.50.200 -SubnetMask 255.255.255.0
Set-DhcpServerv4OptionValue -ScopeId 192.168.50.0 -Router 192.168.50.1 -DnsServer 192.168.50.10

[5/6]Create OUs and user accounts

Separated users and computers into their own organizational units so Group Policy can target each one later. Created three domain users.

New-ADOrganizationalUnit -Name "Lab Users"
New-ADOrganizationalUnit -Name "Lab Computers"
New-ADUser -Name "Jane Doe" -SamAccountName jdoe `
  -Path "OU=Lab Users,DC=emillab,DC=local" `
  -AccountPassword (Read-Host -AsSecureString "Password") -Enabled $true
# Repeated for John Smith (jsmith) and Peter Parker (pparker)

[6/6]Build CLIENT01 and join the domain

Windows 11 requires TPM 2.0 and at least two cores, so the VM got a virtual TPM before install. After setup it pulled an address from DHCP, joined the domain, was renamed to match its VM name, and was moved into the Lab Computers OU.

# On the host
Set-VMKeyProtector -VMName CLIENT01 -NewLocalKeyProtector
Enable-VMTPM -VMName CLIENT01
Set-VMProcessor -VMName CLIENT01 -Count 2

# On CLIENT01
Add-Computer -DomainName emillab.local -Credential emillab\Administrator -Restart
Rename-Computer -NewName CLIENT01 -DomainCredential emillab\Administrator -Restart

# On DC01
Get-ADComputer CLIENT01 | Move-ADObject -TargetPath "OU=Lab Computers,DC=emillab,DC=local"

# Phase 2: permissions assigned to a group, settings delivered by GPOs linked to OUs

GPOLinked toWhat it does
------------------------

Lab Users - RestrictionsLab Users OUBlocks Control Panel and PC settings
Lab Computers - RDP UsersLab Computers OUAdds the Lab Staff group to the local Remote Desktop Users group

[1/4]Create a security group

Permissions go to a group, not to individual users, so adding or removing staff is a single change.

New-ADGroup -Name "Lab Staff" -GroupScope Global -GroupCategory Security -Path "OU=Lab Users,DC=emillab,DC=local"
Add-ADGroupMember -Identity "Lab Staff" -Members jdoe,jsmith,pparker

[2/4]Create a file share with share and NTFS permissions

Access to a network share requires both the share permission and the NTFS permission to allow it, and the more restrictive of the two wins.

New-Item -Path "C:\Shares\LabShare" -ItemType Directory
New-SmbShare -Name "LabShare" -Path "C:\Shares\LabShare" -FullAccess "EMILLAB\Domain Admins" -ChangeAccess "EMILLAB\Lab Staff"
icacls "C:\Shares\LabShare" /grant "EMILLAB\Lab Staff:(OI)(CI)M"

[3/4]Build and link the GPOs

The Control Panel restriction was scripted in PowerShell. The drive map and local group membership use Group Policy Preferences, configured in the Group Policy Management Editor.

# Restrictions GPO (scripted)
New-GPO -Name "Lab Users - Restrictions" | New-GPLink -Target "OU=Lab Users,DC=emillab,DC=local"
Set-GPRegistryValue -Name "Lab Users - Restrictions" `
  -Key "HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer" `
  -ValueName "NoControlPanel" -Type DWord -Value 1

# Drive Map GPO (GUI): User Configuration > Preferences > Windows Settings > Drive Maps
#   Update, \\DC01\LabShare, drive S:, reconnect
# RDP Users GPO (GUI): Computer Configuration > Preferences > Control Panel Settings > Local Users and Groups
#   Update "Remote Desktop Users (built-in)", add EMILLAB\Lab Staff

[4/4]Apply and verify on CLIENT01

gpupdate /force
gpresult /r /scope computer                 # Lab Computers - RDP Users applied
Get-LocalGroupMember "Remote Desktop Users" # EMILLAB\Lab Staff
gpresult /r                                 # as jdoe: both Lab Users GPOs applied

INC-0001"I'm locked out of my computer"Resolved

User
Jane Doe (jdoe)
Symptom
Sign-in on CLIENT01 fails with "The referenced account is currently locked out and may not be logged on to."
Setup
Domain lockout policy set to 5 bad attempts, 15-minute lockout and observation window. Five wrong passwords entered on CLIENT01.
Diagnosis
Get-ADUser showed LockedOut = True and BadLogonCount = 5. Security event 4740 on DC01 identified the lockout source as CLIENT01, the check used to track down a device with a stale saved password.
Resolution
Unlock-ADAccount jdoe; user signed in with the correct password.
# Lockout policy (Default Domain Policy)
Set-ADDefaultDomainPasswordPolicy -Identity emillab.local -LockoutThreshold 5 `
  -LockoutDuration 00:15:00 -LockoutObservationWindow 00:15:00

# Diagnose
Get-ADUser jdoe -Properties LockedOut, BadLogonCount, LockoutTime |
  Select-Object Name, LockedOut, BadLogonCount, LockoutTime
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4740} -MaxEvents 5 |
  Format-List TimeCreated, Message   # Caller Computer Name: CLIENT01

# Fix
Unlock-ADAccount jdoe

INC-0002"I forgot my password"Resolved

User
Peter Parker (pparker)
Symptom
User can't remember their password.
Diagnosis
Identity confirmed (lab scenario). No lockout or disabled flag, so a password reset was the right fix.
Resolution
Set a temporary password and required a change at next sign-in, so the help desk never knows the user's real password. The first temporary password was rejected: the domain's complexity rules apply to admin resets too. At sign-in, Windows showed "The user's password must be changed before signing in" and prompted for a new one. Tested in a basic VM session, since Remote Desktop-style sessions often can't complete a forced change at sign-in.
Set-ADAccountPassword pparker -Reset -NewPassword (Read-Host -AsSecureString "Temp password")
Set-ADUser pparker -ChangePasswordAtLogon $true

INC-0003"It says my account has been disabled"Resolved

User
John Smith (jsmith)
Symptom
Sign-in fails with "Your account has been disabled. Please see your system administrator."
Setup
Account disabled with Disable-ADAccount jsmith to simulate an offboarding mistake.
Diagnosis
Search-ADAccount -AccountDisabled -UsersOnly listed jsmith alongside the built-in Guest and krbtgt accounts, which are disabled by design. Get-ADUser confirmed Enabled = False.
Resolution
Enable-ADAccount jsmith. In a real environment, confirm with the manager or HR before re-enabling an account.
Search-ADAccount -AccountDisabled -UsersOnly | Select-Object Name, SamAccountName
Get-ADUser jsmith | Select-Object Name, Enabled
Enable-ADAccount jsmith

INC-0004"My settings stopped working"Resolved

User
Peter Parker (pparker)
Symptom
User signs in normally, but Control Panel is no longer blocked. Nothing looks broken from the user's side.
Setup
User object moved from the Lab Users OU to the default Users container.
Diagnosis
gpresult /r as pparker showed CN=Peter Parker,CN=Users and no Lab Users GPOs applied. The S: drive was still mapped: it is a Group Policy Preference, which stays in place after its GPO stops applying unless "Remove this item when it is no longer applied" is set. The Control Panel block is a Policy, which Windows removes automatically. Remote Desktop kept working because that GPO targets the computer and the Lab Staff group, not the user's OU.
Resolution
Moved the account back to Lab Users. After signing out and back in, gpresult showed both GPOs applied and Control Panel was blocked again.
# Diagnose (as the user, on CLIENT01)
gpresult /r   # CN=Peter Parker,CN=Users,...  -> Lab Users GPOs missing

# Fix (on DC01)
Get-ADUser pparker | Move-ADObject -TargetPath "OU=Lab Users,DC=emillab,DC=local"

# Unplanned problems hit during the build: symptom, root cause, and fix

New-ADUser : The specified account already exists

+ CategoryInfo : ResourceExists  |  after an earlier password complexity error

SymptomThe first attempt to create jdoe failed on password complexity. Retrying said the account already existed.
Root causeNew-ADUser creates the account object first, then sets the password. When the password was rejected, a disabled account with no password was left behind.
FixReset the password on the existing account and enabled it with Set-ADAccountPassword -Reset and Enable-ADAccount, then confirmed Enabled = True.

Get-ADComputer : Cannot find an object with identity: 'CLIENT01'

+ CategoryInfo : ObjectNotFound  |  after a successful domain join

SymptomThe client joined the domain, but AD had no computer named CLIENT01.
Root causeCLIENT01 was only the Hyper-V VM name. Windows setup had auto-named the computer DESKTOP-P26AUJ7, and that name joined the domain.
FixListed all computer objects with Get-ADComputer -Filter *, renamed the machine with Rename-Computer -DomainCredential, then moved it to the Lab Computers OU.

To sign in remotely, you need the right to sign in through Remote Desktop Services

+ Signing in to CLIENT01 as EMILLAB\jdoe

SymptomDomain Administrator could sign in to the client, but standard user jdoe was blocked.
Root causeHyper-V Enhanced Session mode connects over Remote Desktop. Standard users aren't in the Remote Desktop Users group by default.
FixUsed a basic session as a temporary workaround, then fixed it properly in Phase 2: a GPO linked to Lab Computers adds the Lab Staff group to Remote Desktop Users, so every domain-joined machine gets the right automatically.

Get-LocalGroupMember "Remote Desktop Users" : (no output)

+ gpresult showed Lab Computers - RDP Users applied, but jdoe was still blocked

SymptomThe GPO appeared under Applied Group Policy Objects, but the local Remote Desktop Users group on CLIENT01 was still empty.
Root causeThe group name was typed into the Local Group preference instead of picking Remote Desktop Users (built-in) from the dropdown. The built-in option targets the group by its well-known SID; a typed name has to match exactly.
FixReselected the built-in group from the dropdown and added Lab Staff with the browse button so the name resolved. After gpupdate /force, Lab Staff appeared in the group. Lesson: gpresult proves a GPO arrived, not that its settings are correct.

WARNING: DC01 clock set to the wrong time zone

+ Found while reviewing the server after promotion

SymptomThe domain controller's clock was two hours behind local time.
Root causeThe server defaulted to Pacific time. Kerberos authentication depends on clocks staying in sync across the domain.
FixSet-TimeZone -Id "Central Standard Time" on DC01. Domain members sync time from the DC.

New-ADUser : The object name has bad syntax

+ Typos in commands

SymptomSeveral commands failed: a misspelled cmdlet, a missing closing quote, and a stray space before a parameter.
Root causeThe distinguished name used DC-emillab instead of DC=emillab. The error message pointed straight at the object name.
FixRead the error text closely and corrected each command. Lesson: PowerShell errors usually tell you exactly which part is wrong.
